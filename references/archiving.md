# 定稿双份归档

## 固定保存位置

每篇朋友圈经用户确认定稿后，自动保存两份，无需再询问保存许可：

- 本地仓库：`output/moments/YYYY-MM-DD/<归档ID>/content.md`。
- Obsidian 目录：项目 `.moments.local/obsidian-dir` 中配置的目录，或显式传入的 `--obsidian-dir`。。
- Obsidian 月文件：`微信朋友圈YYYY年M月.md`，例如 `微信朋友圈2026年11月.md`、`微信朋友圈2026年12月.md`、`微信朋友圈2027年1月.md`。

归档使用项目配置指定的目标。未配置 Obsidian 时，本地副本仍然保存，设置目录后可用相同日期补写。

按 Asia/Singapore 的确认日期归档，明确指定日期时使用用户给出的日期。未定稿的草稿、问答历史和开发说明不作为完成的朋友圈归档。定稿归档仅表示文案确认，不代表已经发到微信。

## 执行

常规创作按 [工作台与持久状态](workbench.md) 使用 `workflow.py confirm`，同时保存版本与确认状态；它调用本技能的 [scripts/archive_moment.py](../scripts/archive_moment.py)。两者只依赖 Python 3.10+ 标准库，适用于本机 macOS，会创建缺失的目录和月文件，保留既有笔记，追加带唯一标记的条目。下方独立脚本用于旧归档兼容、维修和隔离测试；不能用它绕过常规创作的持久状态。

先把已确认的正文原样写入一个 UTF-8 输入文件，不含定稿确认问题、解释、分析或提示词。正文中的链接、表情、段落与用户指定句子应完整保留。归档标题取一个简短、客观的主题标签，仅用于月文件的条目标题，不添加到朋友圈正文。

调用示例（输入文件须先用实际定稿创建）：

```bash
python3 scripts/archive_moment.py \
  --text-file /private/tmp/moments-confirmed.txt \
  --title '实际文案主题' \
  --date 2026-11-12 \
  --confirmed
```

`--confirmed` 只能在对话中已经获得该版定稿确认后使用；参数本身不能代替用户确认。不传 `--date` 时按本机时间转换至 Asia/Singapore 取当天日期。重试时保留首次使用的日期，避免跨天后误记成新稿。

默认仓库是脚本所在项目，Obsidian 目录从本地配置读取。`--repo-root`、`--obsidian-dir` 可用于用户要求的新位置或隔离测试；日常归档不擅自修改。不要把正文拼进 shell 命令，使用输入文件传递。

脚本输出 JSON，包含 `ok`、`repo_saved`、`obsidian_saved`、`entry_id`、`repo_file`、`obsidian_file` 和各处写入动作。保存后读取两个目标，核对正文与用户确认的版本一致，再给出真实文件链接。

## 去重、修订与失败续做

- 日期与正文决定归档 ID。同日相同正文再次执行时复用仓库文件，Obsidian 不重复追加；重画图片也不重新插入正文。
- 同一份正文仅改归档标题后重试时，保留月文件中首次写入的标题，不生成重复条目。
- 正文改动且用户重新确认后，作为新的定稿记录保存。保留此前版本，不覆盖旧文案或重写整个月文件；正文中不擅自加“更正版”等字样。
- 仓库保存成功但 Obsidian 失败时，保留仓库副本，说明具体失败与待补写位置，修复问题后用相同正文和日期重试。不能把部分成功报告成全部完成。
- 工作台确认时会保存日期和已配置的 Obsidian 目录，后续核对或重试沿用该次目标。确认时尚未配置目录的稿件可以在配置后补写。
- 检测到同条归档被手工修改或出现不完整记录时，停止覆盖该记录并核对差异；不能为了继续而删除历史内容。
- 无论配图是否生成成功，已确认的正文都先执行双份保存。归档有未解决问题时仍要明确报告，不能以图片交付代替 Obsidian 写入。

月文件只保留正文及日期、主题、隐藏归档标记。图片默认保留在仓库的同条归档目录中，不因本次文字归档要求自动往知识库复制图片、原始聊天记录或整份人设。

## 验证

运行 [scripts/test_archive_moment.py](../scripts/test_archive_moment.py) 检查双份正文一致、保留月文件内容、重复去重、修订留存、跨月跨年、未确认拒绝写入、部分失败重试与本机并发追加。测试使用临时目录，不向真实知识库写入测试文案。
