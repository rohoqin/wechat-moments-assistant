# 定稿与朋友圈配图

## 确认对应的文案

使用 [工作台与持久状态](workbench.md) 的工作流保存草稿、正文版本、用户明确确认、风格和图片关联。对话中的推断不能覆盖已保存的实际状态；无需额外安装数据库。

确认只作用于用户明确选择的正文。提出修改时，先保存并交付新版，再确认新版。不要一边替用户修改，一边替用户认定修改后已经定稿。跨聊天先读取工作流记录；记录缺失或目标有歧义时，需要用户提供已定稿正文或明确选择，不能从开发窗口的讨论推断另一条朋友圈已定稿。

风格可以在写稿时、确认时或出图后指定。例如“水彩”“写实摄影感”“极简插画”“这次用黑白线稿”，都只作用于当前这条，除非用户明确要求长期使用。“自动”表示由助手选择，不是还要追问的缺失信息。仅回复风格不代表文案定稿；如果之前还未确认，先完成定稿确认。

用户说“定稿，用水彩，直接生成”时先按 [双份归档规则](archiving.md) 保存正文，再直接生图；不要再问一次定稿、风格或是否执行。用户说“定稿，但把最后一句改掉”时，修改后的稿件还需确认。

## 从文案选择画面

以已确认正文为内容依据，提取一个主题、主要情绪和适合呈现的主体。图片补充文案的感受或理解，不要求把全部文字搬到图里。人设的真诚、具体、克制和设计感同时适用于图片；不额外添加营销口号和宏大叙事。

用户未指定风格时，结合内容自动选择，下表是可选方向，不是固定对应关系：

| 文案内容 | 可以考虑的画面与风格 |
| --- | --- |
| 企业 AI、流程、团队协作 | 干净的编辑插画、具体工作场景，或少量元素组成的关系示意；突出一项判断。 |
| 工具体验、项目进展 | 简洁的工作场景或流程插画；有真实截图时可以基于截图编排，不伪造产品界面或运行结果。 |
| 设计、POD、创作实践 | 注重构图、肌理和色彩的设计插画或概念画面；不把概念效果表现成已生产、已售出的实物。 |
| 生活观察、中年转型 | 自然摄影感或温和的叙事插画，依据文案的具体情绪决定，不强行加入科技元素。 |
| 节日祝福、趣味分享 | 温暖的节日画面或轻松插画，保留留白与生活感，不变成促销海报。 |

风格应与用户指定要求相符；明确的构图、色彩、比例、参考图和图中文字优先保留。只指定一个风格名称时自行完成其余合理选择，不再要求确认每个视觉参数。

默认生成 1 张，以方形构图为起点，主体清楚、手机上易看。需要展示步骤或用户明确要求多张时再拆图，不自动生成九宫格、封面套装或多个风格方案。构图要求写进提示词，不虚构工具不支持的尺寸参数或保证未实测的像素尺寸。

默认不放长段文字、引流口号、二维码或署名。必要时用极少的短标签解释画面；用户要求的原句或标题必须逐字核对，不能把未经确认的宣传语加到图里。若要求落款，自媒体用“若洪大叔”，正式场合按本轮要求。

视觉创作可以使用概念和象征画面，但不能冒充用户的真实项目照片、客户现场、产品截图、人物经历或销售证据。需要本人出镜时使用用户提供的可用参考，不能从人设文字猜脸；需要某个真实场景或精确产品外观却缺少素材时，只询问真正缺少的参考，不发送整份人设或历史档案到生图工具。

## 执行生图

实际生成或编辑时，优先使用当前环境的内置 `image_gen` 工具；存在 `imagegen` 技能时读取其相关指导。任务仅是开发本技能时，更新规则与用例即可，不把开发说明当成要配图的成稿。

- 新图提示词包含最终文案要表达的主题、选定风格、主体、构图、情绪、必要的逐字文字和避免项；只传完成画面所需的信息。
- 用户提供参考图时说明用途：风格参考、主体参考或要修改的目标图。编辑本地图片前先实际查看，再使用工具支持的引用方式；保留用户未要求改变的部分。
- 生成真实图片，不能用文字提示词、SVG 占位或示例链接冒充完成。除非用户只要提示词，否则只交提示词不算完成配图。
- 内置生图不要求配置 API Key。工具不可用或失败时如实说明，保留已确认正文与风格以便续做；不能擅自换到需要 Key、安装依赖或可能另行计费的外部 API。
- 生成后实际查看图片，核对主题、风格、中文文字与指定内容；发现具体错误时有针对性修正。不能未经查看就声称图片检查通过。

用户修改图片时按其反馈调整；文案没有改变，就继续沿用其已确认状态。用户要求不要图片了时停止该条配图流程。

## 保存与交付

文案确认后即先双份归档，不等待图片成功。生图前读取工作流 `image-request`；内置工具返回图片后实际查看并展示，通过 `attach-image` 保存最终图、实际提示词和风格，绑定到该请求的文案版本。用户已经指定固定的本地仓库和 Obsidian 目录，具体目标以 [双份归档规则](archiving.md) 为准。

文件名与扩展名按真实格式保存，使用新版本避免覆盖现有图。绑定的正文要与用户确认的那版一致，提示词可单独存成 `image-prompt.txt`，不塞进可直接复制的正文。跨天重画或只改图片时继续使用这条正文原有的归档目录，不另追加 Obsidian 条目。

工具只返回内联图片或下载入口、无法取得本地文件时，使用其真实输出展示和交付，不虚构已保存的文件路径，也不输出 base64。工具提供本地文件时报告实际保存位置；生图方式与提示词可用简短说明或真实提示词文件链接交付，不把技术参数变成用户必须完成的操作。

最终交付图片预览与可用的原图文件或工具提供的下载入口，必要时简短标明所用风格。无需再解释写作过程，也不自动发布到朋友圈。
